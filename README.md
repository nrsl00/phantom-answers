# Phantom Answers

Плагин IntelliJ IDEA для демонстрации ввода заранее подготовленного текста. В режиме **Simulation** каждое обычное нажатие печатной клавиши вставляет очередной символ выбранного `lab1.txt` … `lab9.txt`. В режиме **Normal** редактор работает обычно. Плагин читает встроенные файлы; ответы не генерируются и сетевой сервис не используется.

## Требования

- Целевая IDE: **IntelliJ IDEA 2025.3.5** — именно эта версия указана в сборке. Совместимость с другими версиями отдельно не подтверждена.
- Для сборки: **JDK 21**, настроенный в `JAVA_HOME` и как Gradle JVM в IDEA. Java 8 не подходит. [Требования платформы](https://plugins.jetbrains.com/docs/intellij/build-number-ranges.html).
- Gradle **9.6.1** запускается через включённый Gradle Wrapper; отдельно устанавливать Gradle не нужно.
- Интернет для первой загрузки Gradle, платформы IDEA и зависимостей. Первая сборка может занять время и несколько гигабайт диска.

## Скачать готовый плагин

Собирать проект самостоятельно необязательно:

1. Откройте [GitHub Actions → Build plugin](https://github.com/nrsl00/phantom-answers/actions/workflows/build.yml).
2. Выберите успешный запуск для нужного коммита ветки `main`.
3. В разделе **Artifacts** скачайте `phantom-answers-plugin` (для скачивания нужен вход в GitHub).
4. Распакуйте внешний архив GitHub. Внутри находится установочный `phantom-answers-1.0.0-SNAPSHOT.zip`; его распаковывать не нужно.

[Проверенная сборка от 19 сентября 2026](https://github.com/nrsl00/phantom-answers/actions/runs/35437851709) собрана из коммита `56b0667`. Артефакты хранятся 30 дней. Когда срок истечёт, запустите workflow заново через **Run workflow** (нужны права на репозиторий) или соберите исходники ниже.

## Скачать и собрать

Склонируйте репозиторий либо выберите **Code → Download ZIP** на GitHub и распакуйте его:

```sh
git clone https://github.com/nrsl00/phantom-answers.git
cd phantom-answers
```

Из корня проекта в Windows PowerShell:

```powershell
java -version
.\gradlew.bat buildPlugin
```

В macOS / Linux:

```sh
java -version
./gradlew buildPlugin
```

Готовый установочный архив: `build/distributions/phantom-answers-1.0.0-SNAPSHOT.zip`.
**Download ZIP на GitHub скачивает исходники, а не установочный плагин.** Для установки нужен результат `buildPlugin`.

## Установить

1. Скачайте готовый установочный ZIP из GitHub Actions или соберите его по инструкции выше.
2. В IDEA откройте **Settings → Plugins → ⚙ → Install Plugin from Disk…**.
3. Выберите `phantom-answers-1.0.0-SNAPSHOT.zip` (скачанный или из `build/distributions/`), не распаковывая его.
4. Примените изменения и перезапустите IDEA, если она предложит это сделать.

[Официальная инструкция установки](https://www.jetbrains.com/help/idea/managing-plugins.html#install_plugin_from_disk).

## Пользоваться и менять горячие клавиши

| Действие | Сочетание по умолчанию | Имя в поиске действий / Keymap |
| --- | --- | --- |
| Переключить Normal / Simulation | `Ctrl+Shift+Q` | `Toggle Phantom Simulation` |
| Выбрать лабораторию 1–9 с начала | `Ctrl+Alt+1` … `Ctrl+Alt+9` | `Phantom Lab 1` … `Phantom Lab 9` |

1. Откройте обычный редактируемый файл проекта, поставьте курсор в место вставки.
2. Нажмите `Ctrl+Shift+Q`: появится уведомление `Phantom mode: SIMULATION`.
3. Нажмите, например, `Ctrl+Alt+1`.
4. Печатайте обычные символы: вместо них появится текст выбранной лаборатории, по одному символу за нажатие.
5. Для возврата к обычной печати нажмите `Ctrl+Shift+Q` и проверьте уведомление `NORMAL`.

Выбор лаборатории в Normal ничего не делает. В Simulation без выбранной лаборатории или после окончания текста печатные клавиши ничего не вставляют. Выберите лабораторию заново или вернитесь в Normal. Повторный выбор начинает текст сначала, **не удаляя уже вставленное**. Переключение Normal / Simulation сохраняет позицию чтения.

Если сочетание занято IDE или системой, откройте **Settings → Keymap**, найдите действие по имени и назначьте удобное сочетание. Это особенно полезно на macOS и при нестандартной раскладке: отдельные сочетания с Command не заданы. Действия также доступны через **Find Action**.

## Заменить `lab1.txt` … `lab9.txt`

Файлы находятся в `src/main/resources/labs/`. Отредактируйте нужный файл как обычный текст **UTF-8**, желательно с переносами строк LF. Сохраните имена `lab1.txt` … `lab9.txt`: загрузчик использует именно их.

Файлы встроены в плагин при сборке. После изменения снова выполните `buildPlugin`, установите новый ZIP и перезапустите IDEA. Изменение файла в исходниках не обновляет уже установленный плагин автоматически. Содержимое может быть любым текстом; плагин не компилирует примеры. Для запуска Java-примера используйте соответствующее имя файла, например `Lab1.java`.

## Открыть проект и запустить тестовую IDEA

Откройте корень проекта в IntelliJ IDEA как Gradle-проект и дождитесь синхронизации. В **Settings → Build, Execution, Deployment → Build Tools → Gradle** выберите JDK 21 для Gradle JVM.

Запустите сохранённую конфигурацию **Run IDE with Plugin** или:

```powershell
.\gradlew.bat runIde
```

На macOS / Linux используйте `./gradlew runIde`. Откроется отдельная тестовая IDEA с плагином. Создайте в ней проект и проверьте переключение режима, выбор лаборатории и ввод. Её профиль и кэш находятся в `.intellijPlatform/` и не включаются в Git.

Проверка сборки:

```powershell
.\gradlew.bat check buildPlugin verifyPluginStructure
```

Автоматических тестов поведения в исходном проекте нет: успешный `check` не заменяет проверку печати в IDEA. Конфигурация **Run Verifications** вызывает `verifyPlugin`; для проверки других IDE потребуется настроить список целевых IDE в Gradle.

## Структура

- `src/main/java/com/phantomanswers/` — режим, обработчик печати, загрузчик текста и действия.
- `src/main/resources/labs/` — девять текстовых примеров.
- `src/main/resources/META-INF/plugin.xml` — описание плагина и горячие клавиши.
- `src/main/kotlin/` и `resources/messages/` — сохранённое демонстрационное окно `My Tool Window` из шаблона; оно не управляет Simulation.
- `gradle/`, `gradlew`, `gradlew.bat` — сборка и Wrapper.
- `.run/` — переносимые конфигурации запуска IDEA.

## Ограничения текущей версии

- Режим и позиция текста общие для всех открытых проектов в одном процессе IDEA и сбрасываются при перезапуске.
- Обработчик заменяет обычный символьный ввод. Вставка из буфера, Enter, Tab, Backspace, выделение и несколько курсоров не реализованы как полноценное воспроизведение текста; используйте один курсор в обычном редактируемом файле.
- Режим определяется уведомлением; постоянного индикатора и отдельного окна выбора лаборатории нет.
- Обработчик установлен глобально и не восстанавливается при динамической выгрузке плагина. После отключения, обновления или удаления перезапускайте IDEA.
- Сохранены диагностические сообщения в журнале и демонстрационное окно шаблона.
- Лицензия проекта пока не выбрана. Отдельный файл `LICENSE` отсутствует; лицензии сторонних компонентов сохраняют силу.

Секреты, личные настройки, `.idea/`, `.gradle/`, `.kotlin/`, `.intellijPlatform/`, `build/` и `out/` не должны попадать в репозиторий. Не помещайте приватные данные в lab-файлы: они входят в исходники и установочный ZIP.

## Статус проверки

19 сентября 2026 на чистом GitHub Actions runner (Ubuntu, JDK 21) успешно выполнено:

```sh
./gradlew --no-daemon --console=plain --stacktrace check buildPlugin verifyPluginStructure
```

[Журнал успешной сборки](https://github.com/nrsl00/phantom-answers/actions/runs/35437851709). Скомпилированы Java- и Kotlin-исходники, создан установочный ZIP, проверена структура плагина. В архиве присутствуют все девять lab-файлов и 17 скомпилированных классов. Все девять Java-примеров также отдельно проверены компилятором JDK 21; в `lab2.txt` исправлена пропущенная закрывающая скобка.

IntelliJ Platform Gradle Plugin обновлён до **2.19.0**: эта версия исправляет конфликт параллельной подготовки основных и тестовых классов, вызывавший ошибку `1 >= 1` в версии 2.18.1. [Описание исправления JetBrains](https://github.com/JetBrains/intellij-platform-gradle-plugin/releases/tag/2.19.0).

Автоматическая сборка запускается при push в `main`, pull request и вручную. `check` не запускает тесты поведения: в проекте пока нет тестовых классов. Ручная проверка горячих клавиш в открытой IDEA и полная проверка бинарной совместимости через `verifyPlugin` пока не выполнены. Компилятор сообщает об устаревшем API в `ToggleSimulationAction`; это предупреждение не блокирует сборку.

Локальная изолированная Windows-среда по-прежнему ограничивает доступ Java к JAR-файлам (`AccessDeniedException`). Успешная сборка на GitHub позволяет получить установочный ZIP независимо от этой ошибки среды. Публикации в JetBrains Marketplace нет.
